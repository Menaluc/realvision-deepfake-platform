# RealVision Deepfake Platform

Deepfake video detection: upload a short video and get a real/fake verdict, confidence, the sampled frames and Grad-CAM attention heatmaps.

EfficientNet-B0 processes 16 sampled frames, the frame representations are averaged, and the resulting video representation is classified as real or fake.

One FastAPI process serves both the API and the built React frontend. The detection model's behavior is fixed: a parity test shows the platform returns exactly the same probabilities as the original (V1) inference code.

## Tech stack

- **Frontend:** React 19, TypeScript, Vite, Vitest
- **Backend:** Python 3.11, FastAPI, uv, pytest, ruff
- **ML:** PyTorch, timm (EfficientNet-B0), decord, OpenCV

## Requirements

- Python 3.11 and [uv](https://docs.astral.sh/uv/)
- Node.js 20.19+ or 22.12+
- The model checkpoint at `backend/models/baseline_best.pt`. It is not in this repository; copy it there by hand. Without it the app still starts, in a degraded mode (see [Model availability](#model-availability)).

Install the dependencies once:

```bash
cd backend && uv sync
cd frontend && npm install
```

## Running

### Development (two terminals)

Vite serves the frontend with hot reload and forwards `/api` to the backend.

```bash
# Terminal 1: the API on :8000
cd backend
uv run uvicorn app.main:create_app --factory --port 8000

# Terminal 2: the frontend on :5173
cd frontend
npm run dev
```

Open http://localhost:5173.

### Single process (production-like)

FastAPI serves `frontend/dist` at `/` when it exists.

```bash
cd frontend && npm run build
cd backend && uv run uvicorn app.main:create_app --factory --port 8000
```

Open http://localhost:8000. Rebuild the frontend after changing it, or the old build is served.

`--factory` is required: there is no module-level app, so importing the code never loads the model. Run **one worker only** (the default): analyses are kept in an in-memory cache, so a second worker wouldn't find the frames of an analysis created by the first.

### Settings

All optional, read from the environment at startup:

| Variable | Default | Meaning |
|---|---|---|
| `REALVISION_CHECKPOINT_PATH` | `backend/models/baseline_best.pt` | Model weights |
| `REALVISION_DEVICE` | `cpu` | Set `cuda` to use a GPU |
| `REALVISION_MAX_UPLOAD_BYTES` | `20971520` (20 MB) | Upload limit; the frontend checks the same number in `frontend/src/constants/upload.ts` |
| `REALVISION_CACHE_MAX_ENTRIES` | `20` | Analyses kept in memory |
| `REALVISION_CACHE_TTL_SECONDS` | `1800` | How long an analysis's frames stay available |
| `REALVISION_TEMP_DIR` | system temp | Where uploads are written while they are checked |
| `REALVISION_FRONTEND_DIST` | `frontend/dist` | The built frontend to serve |

A value that can't be parsed stops the app at startup.

### Model availability

If the checkpoint is missing or can't be loaded, the reason is logged and the app runs **degraded**: the page and `/api/health` still work, `/api/health` answers `503 { "status": "degraded", "modelLoaded": false }`, and uploads get `503 MODEL_UNAVAILABLE`. Anything that checks readiness should read `/api/health`, not just whether the process is up.

## API

| Method & path | Returns |
|---|---|
| `POST /api/analyses` (multipart field `video`) | `201 { id, prediction, confidence, probabilities }` |
| `GET /api/analyses/{id}/frames` | The 16 sampled frames with their time in the video |
| `GET /api/analyses/{id}/frames/{index}` | One frame as JPEG |
| `GET /api/analyses/{id}/frames/{index}/attention` | Its Grad-CAM heatmap as a transparent PNG (computed on the first request) |
| `GET /api/health` | Ready or degraded |
| `GET /api/model` | Model details, read from the loaded model |

Errors use one format, `{ "error": { "code", "message" } }`. The full contract, with every error code, is in [docs/ARCHITECTURE.md §2](docs/ARCHITECTURE.md#2-api-contract). FastAPI's interactive docs are at `/docs` while the backend runs.

## Tests

```bash
cd backend
uv run pytest            # unit, API and integration tests
uv run ruff check . && uv run ruff format --check .

cd frontend
npm test
npm run typecheck && npm run lint
```

Most tests need neither the checkpoint nor real videos: unit tests use random weights, API tests use a fake predictor, and test videos are generated by OpenCV. Two groups need local files and skip themselves without them:

- **Integration tests** (`tests/integration/`) need the checkpoint.
- **The parity test** (`tests/integration/test_parity.py`) also needs the sample videos in `samples/real/` and `samples/fake/` at the repository root (not committed). It sends each one through the API and compares the result with the probabilities that V1's own code produced, recorded in `backend/tests/fixtures/parity_baseline.json` by `backend/scripts/record_baseline.py`. On the 6 FaceForensics++ clips used, the difference is 0.

## Known limitations

- **Model accuracy is not documented.** The checkpoint holds only the weights, with no training metrics, and none have been measured on a proper test set. On the 6 local sample clips the model was right on 3; that is far too few videos to be a measure, but it is a reason not to treat the verdict as reliable.
- **No face detection.** Frames are center-cropped to 224×224. When the face isn't near the center of the frame, part of it may be cut off.
- **Frames are averaged**, so the model can't see artifacts that only show up as motion between frames.
- **One analysis at a time.** A single lock serializes inference and Grad-CAM; other requests wait.
- **In-memory cache, one worker.** Analyses are lost on restart and expire after 30 minutes.
- **The upload is decoded twice:** once to validate it, once to sample its frames.
